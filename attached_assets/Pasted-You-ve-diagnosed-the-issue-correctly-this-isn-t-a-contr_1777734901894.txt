You’ve diagnosed the issue correctly—this isn’t a controller bug, it’s a **MockMvc vs context-path mismatch**. Spring Boot does **not** automatically apply `server.servlet.context-path` in MockMvc, so your requests are effectively hitting:

```
/api/api/ships   ❌ (what Spring thinks)
```

instead of:

```
/api/ships       ✅ (actual mapping)
```

---

# ✅ Correct Fix

You need to explicitly set the context path in every MockMvc request:

```java
mockMvc.perform(post("/ships")
        .contextPath("/api")
        .contentType(MediaType.APPLICATION_JSON)
        .content(requestJson)
        .header("Authorization", "Bearer " + jwt))
```

### Why this works:

* `.contextPath("/api")` tells MockMvc:

  > “Pretend this request is coming through `/api` as the servlet root”

* Then `/ships` maps correctly to:

  ```
  /api/ships
  ```

---

# ⚠️ Common Mistake (Avoid This)

Do **NOT** do this:

```java
post("/api/ships")   // ❌ wrong in MockMvc with contextPath
```

Combined with `.contextPath("/api")`, this becomes:

```
/api/api/ships
```

# 🧪 Optional Improvement (Cleaner Setup)

Instead of repeating `.contextPath("/api")` everywhere, you can centralize it:

```java
@BeforeEach
void setup() {
    this.mockMvc = MockMvcBuilders.webAppContextSetup(context)
        .defaultRequest(get("/").contextPath("/api"))
        .build();
}
```

👉 Then all requests inherit the context path automatically.
